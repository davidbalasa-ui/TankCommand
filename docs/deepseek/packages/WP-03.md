# Work package WP-03: phone controls, camera and HUD shell

The owner plays on a phone and could not move around the map properly in the WP-02 build. This package
makes the game fully playable by touch on a 915×412 landscape phone, adds the minimap and the on-screen
command bar, and brings mouse controls up to the SOR "Controls and camera" table. No new gameplay rules.

## 1. Camera (src/render/camera.ts)

- One smooth zoom from close 3D to strategic top-down. At maximum zoom-out on the phone viewport the
  **whole map is visible** (all four map corners on screen). Derive the max distance from map size and
  the viewport's aspect and field of view rather than a fixed constant; recompute on resize.
- Pan clamping keeps the **view** useful at the edges: the player must be able to bring every map corner
  to the centre half of the screen at any zoom, and must not be able to scroll off into empty space
  beyond one screen-quarter past the edge.
- Panning speed scales with zoom distance (same finger movement covers more ground when zoomed out).
- Never clips through terrain (keep existing clearance rule). The camera only moves when the player
  moves it or taps an alert/minimap.

## 2. Touch (phone and tablet), exactly the SOR table

| Gesture | Action |
| --- | --- |
| Tap own unit | Select it |
| Tap ground or enemy with units selected | Move there / attack it |
| Double-tap own unit | Select all own units of that type on screen |
| Long-press (≥ 400 ms, placeholder) then drag | Box-select |
| One-finger drag anywhere on the battlefield | Pan camera (ground stays under the finger) |
| Two-finger pinch | Zoom, centred between the fingers |
| Two-finger twist | Rotate camera |
| Two-finger tap | Deselect all |
| Tap or drag on minimap | Jump camera there |

Requirements for robustness:
- A one-finger drag pans **wherever it starts**, including over a unit, the sky/horizon, or the map
  edge. If the ground under the finger can't be picked (sky), fall back to screen-space panning scaled by
  zoom distance. A drag that starts on a unit pans; it does not select or order.
- Pinch and twist can happen in the same gesture. Lifting one finger of a pinch must not cause a tap,
  an order or a camera jump.
- The canvas has `touch-action: none`; the page never scrolls, zooms or shows a context menu on long
  press. Disable text selection on the HUD.
- Gesture thresholds are constants in `src/sim/tuning.ts` or a new `src/ui/inputTuning.ts`.

## 3. Mouse and keyboard (desktop), add what is missing from the SOR table

- Right-drag **or** middle-drag pans (ground stays under the cursor); Q/E or Alt+left-drag rotates
  (middle-drag rotation from WP-02 moves to Alt+left-drag).
- Mouse wheel zooms towards the cursor point.
- Arrow keys and W/A/D pan; **S stays stop** (SOR). Edge-scroll stays.
- H = hold position, S = stop, A then left click = attack-move.
- Ctrl+1–9 assigns a control group, 1–9 selects it, double-tap the number centres the camera on it.
- Double-click own unit selects all of that type on screen.
- Click or drag on the minimap jumps the camera; right click on the minimap orders a move there.
- Space jumps to the latest alert (alerts arrive in later packages; keep a stub alert list now).

## 4. New orders in the sim (src/sim/commands.ts)

- `hold` (fire at anything in range, never move), `attackMove` (move, stopping to fight anything met),
  and queued waypoints: `move` with `queue: true` appends instead of replacing (already in the schema;
  make it work and show the queued path). Touch: on-screen "Queue" toggle.
- Unit stance is part of world state and saves.

## 5. HUD shell (src/ui, DOM over the canvas)

Laid out for the phone first. Thumb-reachable, nothing overlapping, each control ≥ 44×44 px.

- **Minimap**, bottom-left, about 120×120 px on the phone (scales up on larger screens): terrain height
  colours, own units (blue), visible enemies (red), camera view outline (the actual ground footprint of
  the view, a quadrilateral). Drawn on its own 2D canvas, redrawn at most 5 times a second.
- **Command bar**, right edge, vertical on the phone: Attack-move, Hold, Stop, Queue toggle, and a
  "Groups" button that opens a strip of groups 1–5 (tap = select, long-press = assign current selection,
  second tap on the selected group = centre camera). Buttons are disabled (greyed) when nothing is
  selected.
- **Selection panel**, bottom-centre, compact: count and hit-point bars of selected units; tapping one
  icon narrows the selection to that unit.
- **Top bar**: placeholder resource readout (shows "—" until WP-04), pause button (opens the existing
  pause screen), a game clock.
- **Left-handed layout** setting swaps the command bar and minimap sides; store it in settings.
- Health bars over units when damaged or selected.

## 6. Requirement IDs

| ID | Requirement |
| --- | --- |
| TCH-01 | One-finger drag pans the camera from any start point (ground, unit, sky, map edge); ground under the finger moves with it when pickable. |
| TCH-02 | Pinch zooms around the midpoint; twist rotates; both in one gesture; lifting a finger never issues an order. |
| TCH-03 | Two-finger tap deselects; double-tap selects same-type units on screen; long-press-drag box-selects. |
| TCH-04 | No page scroll, browser zoom, text selection or context menu during any gesture. |
| CAM-03 | Fully zoomed out on the phone viewport, all four map corners are on screen. |
| CAM-04 | Every map corner can be brought into the centre half of the screen at min and max zoom; the view never leaves more than a quarter screen of empty space. |
| MM-01 | Minimap shows terrain, own and visible enemy units, and the camera footprint, and updates as the camera moves. |
| MM-02 | Tapping/clicking or dragging the minimap moves the camera target to that map point; right click orders a move. |
| HUD-01 | Command bar buttons (attack-move, hold, stop, queue, groups) work by touch and are disabled with no selection. |
| HUD-02 | On phone, tablet and desktop, no two HUD elements overlap, touch targets are ≥ 44×44 px and text is ≥ 12 px (measured from bounding boxes in e2e). |
| HUD-03 | Left-handed layout mirrors minimap and command bar and persists across reload. |
| HUD-04 | Selection panel shows selected units and narrows selection on tap. |
| ORD-01 | Hold: unit fires at enemies in range and never moves, even when attacked. |
| ORD-02 | Attack-move: unit moves to the point but engages enemies met on the way, then continues. |
| ORD-03 | Queued waypoints are followed in order and shown on screen. |
| GRP-01 | Control groups 1–5 by touch and 1–9 by keyboard: assign, select, double-select centres camera. |
| DESK-01 | Right/middle-drag pans, Alt+drag and Q/E rotate, wheel zooms to cursor, H/S/A keys work. |
