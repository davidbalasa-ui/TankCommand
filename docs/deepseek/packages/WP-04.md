# Work package WP-04: economy, Landing Pads and orbital drops

Adds the SOR "Orbital drops and Landing Pads", "Economy" and skirmish "Match flow" rules. After this
package the player starts with a pad, mines ore and metal, buys units from the build menu, and wins by
eliminating the enemy. The enemy has no AI yet (WP-07): it gets a pad and a starting force that only
defends itself.

All numbers are placeholders in data (`src/data/*.json` or `tuning.ts`) with the placeholder marker.

## 1. Data

- Extend the unit data sheet and add a **structure** data sheet (`src/data/structures.placeholder.json`
  with its own zod schema): id, name, faction, cost, deliverySec, hp, armor, footprint (cells), sight
  range, model id, placeholder flag.
- Both factions get the same placeholder roster for now (the alien rows are copies with alien ids and a
  different tint): **Landing Pad** (structure), **Ore Miner** (ground worker), **Metal Station**
  (structure, built on a metal deposit), **Tug** (ground worker), the existing tank, plus one cheap
  **Scout** (fast, weak) so the build menu has a choice.
- Map data gains **ore deposits** and **metal deposits**: fixed positions, finite amounts, defined per
  map in data. The WP-02 map gets 4 ore and 2 metal deposits per side, symmetric, all reachable.

## 2. Resources (src/sim/economy.ts)

- Each side has `ore` and `metal` integers, never negative. Start values come from the match setup.
- **Ore miner**: ordered onto an ore deposit, it digs a load (rate and load size in data), drives the
  load to the nearest own pad, and ore is credited **only when the load reaches the pad**. Repeats
  automatically until the deposit is empty. A miner can be ordered to another deposit at any time.
- When a deposit is empty it stays empty; its miner reports "deposit empty" (alert stub) and waits.
  Miner **salvage**: a command dismantles a miner for a refund percentage (data).
- **Metal station** sits on a metal deposit and fills containers over time. A **Tug** assigned to the
  station carries a container to the nearest own pad, where metal is credited. A destroyed tug loses its
  load; a destroyed station stops that income.
- Income never appears from nowhere. Losing every miner and tug stops all income.

## 3. Drops (src/sim/drops.ts)

- `buy` command: item id + receiving pad id. Full cost deducted at order time; refused (with a reason
  code the UI shows) if unaffordable, if the item is not in the side's roster, if the pad is gone, or if
  the side is at the unit cap (cap in tuning, placeholder 200).
- Per-side **queue** with delivery time per item; `cancel` refunds in full before delivery.
- On delivery the unit appears beside the chosen pad (nearest free spot) with a visible drop beam effect
  (renderer: a simple glowing column for 1 s). Structure items (pad, metal station) arrive as a **kit**:
  a pending placement the player places on valid ground (simple rule for now: clear, inside the map, not
  overlapping; metal station only on a metal deposit). Full placement rules come in WP-05.
- No pad, no delivery: queued items wait; buying is refused with no pad.

## 4. Match flow

- Skirmish setup in code (screen comes in WP-09): two sides, each with one pad, one miner, one tug, two
  tanks, starting ore 500 / metal 100 (placeholders).
- A side is **eliminated** when it has no pads and no units able to fight or build a pad. Last side
  standing wins. Checked every tick. Results screen shows outcome, time, units built and lost, ore and
  metal gathered.

## 5. UI (phone first; extends WP-03's HUD)

- Top bar shows ore, metal, miners + tugs working, unit count / cap.
- **Build menu** button on the command bar opens a bottom sheet on the phone (side panel on desktop):
  items grouped Units / Structures, each with cost, delivery time and a disabled state with the reason
  (can't afford, cap reached). Shows the queue with progress bars and a cancel button per item, and which
  pad receives drops (tap a pad to choose; default last used).
- Structure kit placement: a ghost follows the finger/cursor, green when valid and red when not; confirm
  and cancel buttons on touch.
- Tapping a miner then a deposit orders it to mine; tapping a tug then a station assigns it. Command bar
  shows "Mine", "Assign", "Salvage" when relevant.

## 6. Requirement IDs

| ID | Requirement |
| --- | --- |
| ECO-01 | Ore is credited only when a miner's load reaches a pad; amounts match load size exactly. |
| ECO-02 | Deposits are finite, reach zero and stay empty; the miner stops and reports it. |
| ECO-03 | Metal is credited only when a tug delivers a container to a pad; killing the tug loses the load. |
| ECO-04 | Income stops entirely when every miner and tug is dead. |
| ECO-05 | Resources never go negative under any command sequence (property test with random commands). |
| ECO-06 | Miner salvage refunds exactly the data-sheet percentage. |
| DROP-01 | Buying deducts the full cost at order time; unaffordable, unknown, over-cap and no-pad orders are refused with a reason. |
| DROP-02 | Cancelling a queued item refunds the full cost; delivered items can't be cancelled. |
| DROP-03 | Units are delivered beside the chosen pad after the delivery time; with no pad they wait. |
| DROP-04 | Structure kits are placed only on valid ground; metal stations only on metal deposits. |
| MATCH-01 | Destroying every enemy pad and fighting unit triggers victory; losing your own triggers defeat. |
| MATCH-02 | Results screen shows outcome, time, units built/lost and resources gathered. |
| HUD-05 | Top bar resources update live; build menu shows cost, time, locked reason, queue and cancel, usable by touch on the phone. |
| DET-02 | Economy and drops keep determinism and survive save/load mid-delivery with an identical hash. |
