# Work package WP-06: fog of war, sensors, radar and stealth

Adds the SOR "Vision" section. This must land before the enemy AI (WP-07), because the AI may only use
what its own units can see.

## 1. Vision in the sim (src/sim/vision.ts)

- Per side, a grid of cells (map cell size) with three states: **unexplored**, **explored** (seen
  before, not now), **visible** (seen now). Recomputed at most every 4 ticks (placeholder), from every
  unit and structure's sight range.
- **Line of sight** blocks vision: a cell is visible only if terrain doesn't block the line from the
  viewer's eye height to the cell. Use the same terrain ray test as combat. High ground sees farther
  (eye height from terrain).
- **Sensor range** (beyond sight): enemy units inside a side's sensor range but outside its sight show as
  **anonymous contacts** (position only, no type, owner shown as "unknown"). Radar towers and a mobile
  **Radar** unit (placeholder row) extend sensor range.
- **Stealth** (the WP-05 upgrade): a stealthed unit is never a sensor contact and is only visible within
  a reduced sight range (data multiplier).
- **Explored memory**: structures last seen in explored cells are remembered as "last known" ghosts
  until seen again.
- A per-side **perception query** API in the sim: `perceivedUnits(world, side)` returns only what that
  side may know (visible units with full data, contacts with position only, remembered structures).
  Everything outside the sim that wants enemy information (renderer, HUD, minimap, AI) must use it.

## 2. Rendering and UI (phone first)

- Fog drawn on the terrain: unexplored black, explored dimmed, visible normal. A cheap approach: a
  small data texture of the vision grid sampled by the terrain material, updated when the grid changes.
- Hidden enemy units are **not drawn**, not pickable, not in the minimap, and not in any test-hook
  output meant for the player view. Contacts are drawn as a pulsing neutral symbol, on the map and the
  minimap.
- Settings toggle "Fog of war: on / revealed" (skirmish option later), default on.

## 3. Requirement IDs

| ID | Requirement |
| --- | --- |
| FOG-01 | Each cell is unexplored, explored or visible per side; explored cells stay explored. |
| FOG-02 | Hills block sight: a unit behind a ridge is not visible to an enemy on the other side. |
| FOG-03 | Enemies inside sensor range but outside sight appear only as anonymous contacts; radar extends it. |
| FOG-04 | Stealthed units are never contacts and are visible only within the reduced range. |
| FOG-05 | A hidden enemy is never drawn, pickable, shown on the minimap, or listed by any player-view API (e2e checks the DOM, minimap pixels and renderer object list). |
| FOG-06 | `perceivedUnits` returns only visible units, contacts and remembered structures; a property test confirms it never leaks hidden data. |
| FOG-07 | Fog rendering costs under 2 ms per frame on the phone viewport (measured over 120 frames in e2e with the quality system's timer). |
| DET-04 | Vision is deterministic and survives save/load with an identical hash. |
