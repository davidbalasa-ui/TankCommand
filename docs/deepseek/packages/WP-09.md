# Work package WP-09: missions, campaigns and skirmish setup

Adds the SOR "Campaigns and missions" and "Skirmish mode" frameworks. The real 22+22+5 missions need
Stage 0 research, so this package builds the **system** and a few placeholder missions that exercise
every trigger and action.

## 1. Mission data (src/data/missions/*.json, zod schema)

A mission: id, campaign (`human`, `alien`, `training`), order, title, briefing text, map id, start
forces per side (units, structures, resources, research done), AI side settings (difficulty, optional
script), objectives (primary/optional, text), and triggers.

## 2. Trigger system (src/sim/triggers.ts)

Data-driven only; no mission logic in engine code.
- Conditions: `time` (tick ≥ n), `areaEntered` (side, rectangle, optional unit type), `unitDestroyed`
  (tagged unit), `allDestroyed` (side + type), `resourceReached` (side, ore/metal ≥ n),
  `objectiveDone`, `structureBuilt`, and `and` / `or` / `not` combinators.
- Actions: `spawn` (units for a side at a point, with a drop effect), `message` (text + optional speaker),
  `revealArea`, `setObjective` (add / complete / fail), `grant` (visible scripted resources), `win`,
  `lose`, `aiOrder` (send a tagged AI group to attack or defend a point).
- Triggers fire once unless `repeat: true`. Evaluated every tick in fixed order. State saved.
- Win when every primary objective is complete; lose when any failure condition triggers.

## 3. Placeholder content

- **Training 1** (drops and movement): objectives buy a tank, move it to a marked area.
- **Training 2** (mining): mine 300 ore.
- **Human Mission 1** and **Alien Mission 1**: destroy an enemy base; a protected unit whose death fails
  the mission; a timed reinforcement wave via `spawn`; one optional objective.

## 4. Screens (phone first)

- Title → Campaign select (Training / Human / Alien) → Mission select (locked missions greyed; replay any
  reached) → Briefing (title, text, map preview image rendered from the heightmap, objectives, Start)
  → in-game → Results (Next mission / Retry / Mission list).
- In-game **Objectives** button opens a sheet listing objectives with status; messages from triggers
  appear as a short toast with the speaker name.
- **Skirmish setup** screen: map, your faction, 1–3 AI opponents (faction, difficulty), starting
  resources (low/normal/high), starting units (pad only / pad + force), fog on/revealed. Start.
- Campaign progress (missions unlocked, best result per difficulty) saved through the existing saves/kv
  layer.

## 5. Requirement IDs

| ID | Requirement |
| --- | --- |
| MSN-01 | Mission files validate against the schema; an invalid file is rejected with the field named. |
| MSN-02 | Every condition and action type has a unit test that fires it. |
| MSN-03 | Each placeholder mission can be won and lost by a scripted command stream (headless). |
| MSN-04 | No placeholder mission can reach a state with no way to win or lose (a time limit or loss condition always exists). |
| MSN-05 | Completing a mission unlocks the next; progress persists across reload; reached missions can be replayed. |
| MSN-06 | Objectives sheet and trigger messages work by touch on the phone. |
| SKR-01 | Skirmish setup options all take effect (checked in the started match state), with 1–3 AI opponents. |
| DET-07 | Trigger state survives save/load with an identical hash. |
