# Decisions

| Date | Question | Choice | Evidence | Who |
| --- | --- | --- | --- | --- |
| 2026-10-27 | Separate Vitest config or embed in Vite config? | Separate `vitest.config.ts`. | Keeps Vite build flags separate from unit-runner settings. | DeepSeek (WP-01) |
| 2026-10-27 | How should large native saves and small settings be separated? | Native keys prefixed `setting.` use Preferences; other keys use Filesystem under `saves/<key>.json`. | Matches the platform storage split without changing the public KvStore interface. | DeepSeek (WP-01) |
| 2026-10-27 | How is settings treated when opened from pause? | Settings is an overlay when opened from pause and a normal screen from title. | Required by the overlay/back acceptance flow. | DeepSeek (WP-01) |
| 2026-10-27 | How is the credits file made available to the in-app screen? | Generate both `CREDITS.md` and `public/CREDITS.md` from a single script. | The screen can fetch a static local copy without importing build-specific raw text. | DeepSeek (WP-01) |
| 2026-10-27 | How is the test hook excluded from production builds? | Conditional dynamic import behind `__TEST_HOOK__`. | Rollup removes the dead branch and the test asserts the marker is absent from built JS. | DeepSeek (WP-01) |
| 2026-10-27 | How are autosave slots ordered? | Internal rotating cursor plus `latestAutosave` using the manager and saved timestamps. | Gives deterministic rotation in tests while remaining recoverable after reload. | DeepSeek (WP-01) |
| 2026-10-27 | How is the production-build Playwright check isolated? | Runs only in the desktop project and builds into a temp directory. | Avoids concurrent preview-server and out-dir collisions. | DeepSeek (WP-01) |
| 2026-11-03 | Where do WP-02 game rules live? | Entirely in `src/sim`, with plain `SimUnitType` data passed in by the app. | Keeps the sim headless and prevents JSON/asset imports in sim modules. | DeepSeek (WP-02) |
| 2026-11-03 | How is the map saved? | Save payloads store the seed only and regenerate heights with `generateMap`. | Meets the no-heights-in-saves rule and keeps saves small. | DeepSeek (WP-02) |
| 2026-11-03 | How are group move goals formed? | Golden-angle spiral offsets spaced by `FORMATION_SPACING`. | Gives distinct goals without a table and satisfies the non-pileup rule. | DeepSeek (WP-02) |
| 2026-11-03 | How are HUD clicks kept off the map? | Input listeners attach to the canvas; HUD buttons live in sibling overlays. | Buttons never bubble through the canvas regardless of pointer type. | DeepSeek (WP-02) |
| 2026-11-03 | How does Play again work? | Results routes to `loading`, which the App intercepts to build a fresh skirmish. | Reuses the existing loading transition and guarantees a new skirmish. | DeepSeek (WP-02) |
| 2026-11-03 | How are camera test settings applied? | Test builds expose `setCamera(partial)` in the hook. | Lets pick tests use the real camera at several zoom/yaw values without back-door stepping. | DeepSeek (WP-02) |
| 2026-11-04 | What happens when an attack order's target dies? | The order stays active against the nearest surviving enemy. | Idle units only auto-engage inside weapon range, so a squad that stopped at the edge of range would otherwise park outside every survivor and the skirmish would never resolve. | DeepSeek (WP-02) |
| 2026-11-04 | Does the stuck rule apply to a tank holding position to fire? | No. `isHoldingFirePosition` clears the stuck counter and re-plan budget while an attack order is in range with line of sight. | A stationary firing tank registers `moved < MOVE_EPS` every tick, so it would spend its three re-plans and lose the attack order, after which it only auto-engages inside weapon range and never closes on the survivors. | DeepSeek (WP-02) |
| 2026-11-05 | Which height does `worldToScreen` project? | The terrain mesh's two-triangles-per-cell interpolation, not the bilinear `heightAt`. | Picking raycasts the mesh; projecting with the bilinear height would leave a systematic offset (largest on steep cells) between where a ground point is drawn and where it is picked. | DeepSeek (WP-02) |
| 2026-11-05 | How do browser tests see raw ground picking? | `lastGroundPick()` in the test hook: the world x,z the input layer resolved for the most recent click/tap (null before any, and null when the ray missed the terrain). | Lets INP-01 assert picking precision at maximum zoom and near the map corners, independently of whether the clicked cell is a reachable destination. | DeepSeek (WP-02) |
| 2026-11-05 | How does the browser test select a tank deterministically at any zoom? | `unitScreenCentre(id)` in the test hook: the canvas-space projection of the unit's picking centre, i.e. the exact point `pickUnit` compares against its 24/36 px radius. | `worldToScreen` returns the ground base under the tank, not that centre, and the vertical gap between the two exceeds the pick radius on wide viewports at close zoom — clicking the base there would miss. | DeepSeek (WP-02) |
| 2026-11-06 | How are unit bounds measured? | `unitBounds` unions `Box3.setFromObject` over meshes reached by `traverseVisible`, and the same function drives both the model scale and `unitScreenBounds`. | `Box3.setFromObject` on the whole tree includes children with `visible === false` — the hidden 200×200 ground `Plane` inside the PoC glb made the measured footprint 200 units, collapsing the scale so tanks drew as a few pixels, and simultaneously inflating `unitScreenBounds`. | DeepSeek (WP-02) |
| 2026-11-06 | How is the void outside the map avoided? | A vertical skirt curtain around the map border joins the terrain to a large far plane, and the scene background is a vertical sky gradient texture. | The map is 160 units across, so the screen corners look past its edge; without a skirt the player sees black through the gap between the terrain and the far distance. | DeepSeek (WP-02) |
| 2026-11-06 | Why is the camera default distance 40 and the pitch eased? | `CAMERA_DEFAULT_DISTANCE = 40` and pitch interpolates on `CAMERA_PITCH_CURVE = 0.75`, putting the default at ~49°. | The previous default (60) framed the flattened start bowl plus large black margins; a linear pitch curve would give 45° at that distance, which reads flatter than the ~50° the review asked for. | DeepSeek (WP-02) |
| 2026-11-06 | Why flat-shade the terrain and raycast the skirt? | `flatShading: true` on the terrain material, and `pickGround` raycasts terrain + skirt + far plane. | Faceted lighting is what makes hills legible at RTS distance, and raycasting the skirt means a right-click on visible ground beyond the map edge still issues a (clamped) move. | DeepSeek (WP-02) |
| 2026-11-06 | Why a sky *gradient texture* background? | The background is a 4×256 canvas gradient (`scene.background` = CanvasTexture) with plain hex colour stops. | It removes the flat void above the horizon without adding a skydome mesh or a new asset, and the colour stops are literals so `addColorStop` can never throw at start-up. | DeepSeek (WP-02) |
| 2026-11-07 | Why does `App.sendCommand` re-anchor stale command ticks? | A command whose tick is in the past is stamped with `world.tick + 1`. | The UI computes the target tick from the world it can see, but a slow frame runs several fixed steps at once, so a click could address a tick that had already been stepped — where `stepSimulation` discarded it silently. | DeepSeek (WP-02) |
| 2026-11-07 | Which screen point does box selection test? | The same picking centre that `pickUnit` tests (`unitScreenCentre`). | Box selection previously projected the ground base, a model-height below the clickable point, so a box drawn around four tanks could select only three. | DeepSeek (WP-02) |
| 2026-11-07 | Does a one-finger drag pan when it starts on a tank? | Yes — panning no longer depends on `downUnit`. | Gating the pan on "the press missed every unit" meant a drag that started on a tank did nothing at all. | DeepSeek (WP-02) |
| 2026-11-08 | How long should the typed-lint requirement test be allowed to run? | `[LINT-02]` gets an explicit 60 s budget. | Typed linting (`projectService`) must build a TypeScript program before evaluating a rule; that alone takes 5-7 s on a cold machine, which exceeds vitest's 5 s default. The requirement is *which* rules fire, not lint start-up speed. | DeepSeek (WP-02) |
| 2026-11-08 | Is a touch gesture's pan/box-select classification re-evaluated per move event? | No. A gesture is classified once: the first movement past the 6 px threshold decides it. | Re-checking `longPressReady` on every move meant a drag that had already been panning could flip into a box-select the instant the 400 ms timer fired, discarding the camera movement the player had made. | DeepSeek (WP-02) |
| 2026-11-08 | How does the browser test deliver a synthetic touch gesture? | All pointer events of one gesture are dispatched in a single `page.evaluate` call. | Separate round trips put an uncontrolled amount of wall-clock time between the events; on a loaded runner that exceeded the 400 ms long-press threshold, so a two-event drag became a long-press box-select. | DeepSeek (WP-02) |
| 2026-11-08 | Why does `[INP-01]` no longer pause the sim after each order? | The ground pick is read synchronously and the move order is polled with a bounded `expect.poll` instead of pausing the loop and waiting for a fixed step. | The per-sample pause/resume plus in-page `setTimeout` loop made each of the 15 samples wait on rendered frames; at 1920×1080 with software GL that cost exceeded the test's budget. | DeepSeek (WP-02) |
| 2026-11-08 | Does `setCamera` need a settle delay before projecting? | No. `RenderView.setCamera` applies the view synchronously (`applyCamera` refreshes the camera matrices). | The 80 ms sleep per sample was pure added latency in a 15-sample loop. | DeepSeek (WP-02) |
| 2026-11-09 | How does `[INP-01]` deliver a press and read the resulting pick? | One `page.evaluate` dispatches `pointerdown`+`pointerup` and returns `lastGroundPick()` in the same task. | `locator.click()`/`touchscreen.tap()` go through actionability checks whose latency varies by viewport and machine; a slow runner could leave a tank driving to its destination between samples, and the pick had to be read in a second round trip that could observe an earlier sample's value. | DeepSeek (WP-02) |
| 2026-11-09 | How does `[INP-01]` treat a unit that has already completed the move? | The poll accepts *either* an active order within 1 unit of the clicked point *or* the unit standing within 1 unit of it. | The three reachable sample points are reused at every zoom, and a unit ordered onto a point it already occupies is correctly turned to `idle` on the same tick (`STOP_DISTANCE`), so `units()` never reports a move order. Standing on the clicked point is proof the move target was that point; a click that did nothing leaves the unit elsewhere and still fails. | DeepSeek (WP-02) |
| 2026-11-09 | Why do the HUD Deselect/Stop presses in `[INP-01]` call `element.click()` in-page instead of `locator.click()`? | Same DOM event, no actionability scheduling. | Playwright's `click()` waits for visible/stable/enabled/receives-events before dispatching, which can take hundreds of milliseconds on a loaded runner. In `INP-01` that delay let the tank drive to the next sample point before `Stop` arrived, which is what made the test converge on an already-reached destination. | DeepSeek (WP-02) |
