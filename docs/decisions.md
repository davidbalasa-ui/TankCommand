# Decisions

| Date | Question | Choice | Evidence | Who |
| --- | --- | --- | --- | --- |
| 2026-10-27 | Separate Vitest config or embed in Vite config? | Separate `vitest.config.ts`. | Keeps Vite build flags separate from unit-runner settings. | DeepSeek (WP-01) |
| 2026-10-27 | How should large native saves and small settings be separated? | Native keys prefixed `setting.` use Preferences; other keys use Filesystem under `saves/<key>.json`. | Matches the platform storage split without changing the public KvStore interface. | DeepSeek (WP-01) |
| 2026-10-27 | How is settings treated when opened from pause? | Settings is an overlay when opened from pause and a normal screen from title. | Required by the overlay/back acceptance flow. | DeepSeek (WP-01) |
| 2026-10-27 | How is the credits file made available to the in-app screen? | Generate both `CREDITS.md` and `public/CREDITS.md` from a single script. | The screen can fetch a static local copy without importing build-specific raw text. | DeepSeek (WP-01) |
| 2026-10-27 | How is the test hook excluded from production builds? | Conditional dynamic import behind `__TEST_HOOK__`. | Rollup removes the dead branch and the test asserts the marker is absent from built JS. | DeepSeek (WP-01) |
| 2026-10-27 | How are autosave slots ordered? | Internal rotating cursor plus `latestAutosave` using the manager and saved timestamps. | Gives deterministic rotation in tests while remaining recoverable after reload. | DeepSeek (WP-01) |
| 2026-10-27 | How is the production-build Playwright check isolated? | Runs only in the desktop project and builds into a temp directory. | Avoids concurrent preview-server and out-dir collisions. | DeepSeek (WP-01) |
| 2026-11-03 | Where do WP-02 game rules live? | Entirely in `src/sim`, with plain `SimUnitType` data passed in by the app. | Keeps the sim headless and prevents JSON/asset imports in sim modules. | DeepSeek (WP-02) |
| 2026-11-03 | How is the map saved? | Save payloads store the seed only and regenerate heights with `generateMap`. | Meets the no-heights-in-saves rule and keeps saves small. | DeepSeek (WP-02) |
| 2026-11-03 | How are group move goals formed? | Golden-angle spiral offsets spaced by `FORMATION_SPACING`. | Gives distinct goals without a table and satisfies the non-pileup rule. | DeepSeek (WP-02) |
| 2026-11-03 | How are HUD clicks kept off the map? | Input listeners attach to the canvas; HUD buttons live in sibling overlays. | Buttons never bubble through the canvas regardless of pointer type. | DeepSeek (WP-02) |
| 2026-11-03 | How does Play again work? | Results routes to `loading`, which the App intercepts to build a fresh skirmish. | Reuses the existing loading transition and guarantees a new skirmish. | DeepSeek (WP-02) |
| 2026-11-03 | How are camera test settings applied? | Test builds expose `setCamera(partial)` in the hook. | Lets pick tests use the real camera at several zoom/yaw values without back-door stepping. | DeepSeek (WP-02) |
| 2026-11-04 | What happens when an attack order's target dies? | The order stays active against the nearest surviving enemy. | Idle units only auto-engage inside weapon range, so a squad that stopped at the edge of range would otherwise park outside every survivor and the skirmish would never resolve. | DeepSeek (WP-02) |
| 2026-11-04 | Does the stuck rule apply to a tank holding position to fire? | No. `isHoldingFirePosition` clears the stuck counter and re-plan budget while an attack order is in range with line of sight. | A stationary firing tank registers `moved < MOVE_EPS` every tick, so it would spend its three re-plans and lose the attack order. | DeepSeek (WP-02) |
| 2026-11-05 | Which height does `worldToScreen` project? | The terrain mesh's two-triangles-per-cell interpolation, not the bilinear `heightAt`. | Picking raycasts the mesh; projecting with the bilinear height would leave a systematic offset. | DeepSeek (WP-02) |
| 2026-11-05 | How do browser tests see raw ground picking? | `lastGroundPick()` in the test hook. | Lets INP-01 assert picking precision without depending on whether the clicked cell is a reachable destination. | DeepSeek (WP-02) |
| 2026-11-05 | How does the browser test select a tank deterministically at any zoom? | `unitScreenCentre(id)` in the test hook. | `worldToScreen` returns the ground base under the tank, not the pick centre. | DeepSeek (WP-02) |
| 2026-11-06 | How are unit bounds measured? | `unitBounds` unions `Box3.setFromObject` over visible meshes and drives both model scale and `unitScreenBounds`. | `Box3.setFromObject` on the whole tree includes invisible nodes. | DeepSeek (WP-02) |
| 2026-11-06 | How is the void outside the map avoided? | Skirt + far plane + sky gradient background. | The map is 160 units across; without a skirt the player sees black. | DeepSeek (WP-02) |
| 2026-11-06 | Why is the camera default distance 40 and the pitch eased? | `CAMERA_DEFAULT_DISTANCE = 40`, `CAMERA_PITCH_CURVE = 0.75`. | Puts the default at ~49° pitch. | DeepSeek (WP-02) |
| 2026-11-06 | Why flat-shade the terrain and raycast the skirt? | `flatShading: true`, `pickGround` raycasts terrain + skirt + far plane. | Makes hills legible and keeps a right-click useful on the visible ground beyond the map. | DeepSeek (WP-02) |
| 2026-11-06 | Why a sky *gradient texture* background? | 4×256 canvas gradient (`scene.background` = CanvasTexture). | Removes the flat void without a skydome mesh or new asset. | DeepSeek (WP-02) |
| 2026-11-07 | Why does `App.sendCommand` re-anchor stale command ticks? | A command whose tick is in the past is stamped with `world.tick + 1`. | A slow frame runs several fixed steps at once; a click could address a tick already stepped. | DeepSeek (WP-02) |
| 2026-11-07 | Which screen point does box selection test? | The same picking centre that `pickUnit` tests (`unitScreenCentre`). | Box selection projected the ground base, a model-height below the clickable point. | DeepSeek (WP-02) |
| 2026-11-07 | Does a one-finger drag pan when it starts on a tank? | Yes. | Gating the pan on "the press missed every unit" made a drag that started on a tank do nothing. | DeepSeek (WP-02) |
| 2026-11-08 | How long should the typed-lint requirement test be allowed to run? | `[LINT-02]` gets an explicit 60 s budget. | Typed linting's startup alone exceeds vitest's 5 s default. | DeepSeek (WP-02) |
| 2026-11-08 | Is a touch gesture's pan/box-select classification re-evaluated per move event? | No — the first movement past 6 px decides it. | Re-checking `longPressReady` per move could flip a running pan into a box-select. | DeepSeek (WP-02) |
| 2026-11-08 | How does the browser test deliver a synthetic touch gesture? | All pointer events of one gesture in a single `page.evaluate`. | Round trips let the long-press timer fire mid-drag. | DeepSeek (WP-02) |
| 2026-11-08 | Does `setCamera` need a settle delay before projecting? | No — `RenderView.setCamera` applies the view synchronously. | The 80 ms sleep was pure latency. | DeepSeek (WP-02) |
| 2026-11-09 | How does `[INP-01]` deliver a press and read the resulting pick? | One `page.evaluate` for `pointerdown`+`pointerup`+`lastGroundPick()`. | `locator.click()`/`touchscreen.tap()` actionability plus a second round trip made the pick racy. | DeepSeek (WP-02) |
| 2026-11-09 | Why do the HUD presses in `[INP-01]` call `element.click()` in-page? | Same DOM event, no actionability scheduling. | `locator.click()` can wait hundreds of ms on a loaded runner. | DeepSeek (WP-02) |
| 2026-11-10 | Why did `[INP-01]` fail three rounds in a row on different viewports? | It mixed two independent concerns — raw ground-pick accuracy and live unit orders — in one test that also moved tanks between samples. Split into two tests, both keeping the `INP-01` ID. | Each failure had a different legitimate cause (redirect in the blend ring, clearance from a moved tank, slow HUD press); a single test that drives the tanks, the camera and the pointer target at once cannot be made stable. | DeepSeek (WP-02) |
| 2026-11-10 | How is the pick-accuracy test made stable? | No orders are issued anywhere in the test, so tanks stay at spawn; for each sample the camera target is the sample point itself, and the point is nudged in a spiral until every `unitScreenCentre` is at least `pickRadius + 10` px away; the test asserts against the returned (actual) world point. | With no orders, tank positions never change; with the nudge, no press point can fall in a pick radius. | DeepSeek (WP-02) |
| 2026-11-10 | How is the order-target test made stable? | The sim is paused via `pauseSim(true)` first; one tank is selected; a point in the flat disc (radius ≤ 14 around (-50, -50)) is chosen clear of every unit; a right-click/tap issues the move; `lastIssuedCommand()` is asserted within 1 unit of the chosen point; then unpause. | The order is read from the command the input layer issued, recorded before `sendCommand`, so the assertion cannot race a sim step. The flat disc is guaranteed reachable. | DeepSeek (WP-02) |
| 2026-11-10 | Why are `[INP-01]`'s order targets restricted to the flat start disc? | Sample points sit at radius ≤ 14 around (-50, -50), the disc `generateMap` flattens to height 0. | Outside it the blend ring has real slope, a cell can be blocked, and `findPath` correctly redirects to the nearest reachable cell (MOVE-05), so `orderX/orderZ` would legitimately differ from the click. | DeepSeek (WP-02) |
| 2026-11-10 | Why does `[INP-01]` call `pointerdown`/`pointerup` directly instead of `locator.click()`? | One `page.evaluate` fires both events and reads `lastGroundPick()` in the same task. | The two events must be atomic with respect to the pick read, and `locator.click()`'s actionability checks add hundreds of ms of unrelated latency. | DeepSeek (WP-02) |
| 2026-11-11 | What does the 2 s watchdog freeze threshold do? | It records a `WatchdogReport` (kept as `lastFreezeReport()`) and nothing else; the recovery screen belongs to the 5 s recover threshold. | Spec WP-01 §5.4. Wiring `onFreeze` to `router.go('recovery')` meant a single >2 s frame on a software-rendered device opened the recovery overlay, which hides the in-game HUD; that is what made `[INP-05]`'s `pause.click()` hang on GitHub Actions (2 vCPU, SwiftShader, 1920×1080) and it would hit low-end phones the same way. | DeepSeek (WP-02) |
| 2026-11-11 | What clocks the render channel of the watchdog? | The start of the frame: `beat('render')` runs at the top of `frame`, before the fixed steps and the draw. | "Time since the last frame started" is the only measure that distinguishes a slow frame from a stalled renderer; with the beat taken at the top, a single frame of any duration up to the 5 s recover threshold can never trigger recovery. | DeepSeek (WP-02) |
| 2026-11-11 | Why is `[INP-04]` frame-driven and given an explicit 90 s budget? | Each held key is released as soon as `camera()` reports the movement, touch gestures are read back immediately (all handlers mutate the camera synchronously), redundant `camera()` round trips are removed, and the test declares `test.setTimeout(90_000)`. | The previous version asserted 350 ms after `keyboard.down`, which assumes a frame lands inside that window — false at 1920×1080 under SwiftShader, where the CI log shows 31.2 s for ~25 round trips (≤ ~1.2 s per frame). The revised test needs ~18 round trips plus three poll windows, ≤ ~60 s worst case on that runner, so 90 s leaves headroom while still failing a genuine hang. | DeepSeek (WP-02) |
